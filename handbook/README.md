# 目录

本目录是 Async Handbook 的索引。它的职责是帮助人类和 Agent 从具体场景出发，快速定位到相关章节。每一条描述应当让人读完就知道：这一章解决什么问题、什么时候需要读它。

Handbook 的正文描述当前采用的协作做法，并解释为什么这样做、适用边界是什么，以及不同场景下应如何判断。页面围绕具体问题自然组织，不使用统一模板；平台落地说明不得新增规范正文中不存在的义务。

## 当前内容

- [异步协作介绍](00-about-async-work.md)：理解异步协作解决什么问题、与同步沟通的关系，以及落实异步协作需要哪些思维转变。当你需要向他人解释为什么要异步工作，或者不确定某件事应该异步处理还是同步处理时，从这里开始。
- [异步协作原则](01-async-principles.md)：定义 Handbook 的上位协作原则。当具体规则没有覆盖你的情况、两条规则看似冲突，或者你需要判断一条规则为什么存在时，回到这里找出发点。
- [Handbook 编写规范](02-handbook-writing-guide.md)：说明 Handbook 本身的编写、审阅和维护标准。当你需要新增或修改协作规范，或者审阅别人的变更提案时，按这里的方式判断。
- [Agent 如何使用 Handbook](03-agent-indexing.md)：Agent 查阅、引用和审阅规范的操作方式，以及 Agent 的行动边界。Agent 引用手册或审阅协作产物前应完整阅读本章。
- [知识架构](04-knowledge-base-architecture.md)：信息散落在多个系统、同一件事有不同版本、新成员找不到资料、不确定某条信息应该放在哪里——这些问题说明信息缺少权威位置和清晰入口。本章说明如何根据信息用途和生命周期组织知识，让重要信息能被找到、被信任、被维护。
- [协作文档](05-documentation-standards.md)：写文档（方案、操作说明、知识文章等）时，判断应该提供多少上下文、如何让后来者不需要追问就能继续工作。当你 review 别人的文档、发现读完仍不知道要做什么，或自己被要求“写一份文档”但不知道写到什么程度算合格时，参考本章。
- [任务管理](06-task-management.md)：发起任务、接受任务、更新状态、处理阻塞、完成交接、确认结束。当你收到一条“帮忙看一下”的模糊请求、自己发的任务迟迟没人响应、任务卡住不知道找谁，或者需要把一次口头讨论变成一个真正有人推进的行动时，使用本章。
- [沟通渠道的选择](07-communication-channels.md)：一件事应该发消息、写文档、建任务、开 Issue，还是开会？当你准备发起沟通，或者发现团队过度依赖某一种渠道（比如所有事情都在 IM 里说）时，本章帮助你根据信息用途选择合适载体。
- [项目里程碑](08-project-milestones.md)：项目进展不透明、里程碑一直在滑、不确定某个时间节点是否合理。本章说明里程碑如何服务风险管理和决策检查，而不是变成绩效汇报的日期。
- [会议](09-meetings.md)：异步协作不等于不开会。判断一场会议是否值得开、怎么开才能让没参加的人也受益、会后如何把结论写回权威载体。当你准备发起会议、被拉进一个没有议程的会，或者会议结束后产出不明确时，参考本章。
- [决策记录](10-decision-records.md)：重要决定是谁做的、为什么这样做、如果条件变化了该找谁来改。当你需要记录一个刚刚形成的决定、追溯一个历史决定的背景，或者推动一个悬而未决的问题到结论时，参考本章。
- [组织运行节奏](11-operating-cadence.md)：团队应该多频繁地站会、回顾、规划？当现有节奏变成走过场、信息在两次同步之间丢失，或者团队扩大后原有节奏不再适用时，本章说明如何根据变化速度、风险和受众设计反馈循环。
- [入职、交接与知识传承](12-onboarding-handoffs.md)：新人需要多久才能独立工作？有人离职或换岗时，哪些知识会跟着消失？当你要入职、交接、或者为一个关键人离开做准备时，本章定义上下文传递和知识迁移的最低标准。
- [术语表](13-glossary.md)：查阅手册时遇到不理解的关键术语，来这里找定义。
- [研究材料](research/)：保存会长期影响本项目设计的调查材料；其中内容不是规范正文。

## 阅读顺序

首次参与本项目时，建议先阅读仓库根目录的 [README](../)，再阅读本页、[异步协作原则](01-async-principles.md)、[Handbook 编写规范](02-handbook-writing-guide.md)和[Agent 如何使用 Handbook](03-agent-indexing.md)。

## 如何提出修改

有具体文本可供审阅时，应直接提出修改；问题尚不清楚、影响跨越多个章节或存在明显迁移风险时，可以先展开讨论。所有已经形成的改变都应回到 Handbook 正文，而不是停留在聊天或会议中。
